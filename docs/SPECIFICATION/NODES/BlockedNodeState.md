# Blockedノード状態

## 状態

基本契約、出力フォールバック、診断状態およびログ規則まで確定。

## 発生条件

- 必須入力ポートが未接続である場合、そのノードを `Blocked` 状態とする。
- 必須入力が依存する上流ノードから現在フレームの値を取得できない場合も、そのノードを `Blocked` 状態とする。

## 確定事項

- `Blocked` 状態のノードは、その評価フレームでは処理を実行しない。
- `Blocked` 状態のノードは、その評価フレームの新しい出力値を生成しない。
- 過去フレームの出力がRenderTexture内に残っていても、現在フレームの有効な出力として扱わない。
- `Blocked` 状態のノード出力を必須入力として必要とする下流ノードも `Blocked` 状態にする。
- 上流ノードが `Faulted` で必須入力を取得できない場合も、接続先ノード自身は `Blocked` 状態とする。
- 上流が `UnknownNode` で必須入力を取得できない場合も、接続先ノードを `Blocked` 状態とする。
- `Blocked` の伝播は依存する下流だけに限定し、独立したグラフの枝は通常どおり評価する。
- ノードの状態には、原因となった未接続ポートまたは上流ノードを特定できる情報を含める。
- ノードエディターは `Blocked` 状態とその原因を表示する。
- 必須入力がすべて利用可能になった次の評価フレームから、ノードは通常評価へ戻る。
- 任意入力へ接続された上流ノードが `Blocked` の場合は、その任意入力の既定値へフォールバックし、接続先ノードへ `Blocked` を伝播させない。
- Program出力まで `Blocked` が伝播した場合は最後の正常フレームを表示し、正常フレームがまだ存在しない場合は黒を表示する。
- 操作用Previewには `Blocked` の原因を示すエラー表示を重ね、Program映像には重ねない。

## 設計意図

- 不完全なグラフを実行中に編集できるようにしながら、無効な入力でノードを評価しない。
- 1つの不完全な枝によって、無関係なProgramまたはPreviewの枝まで停止することを防ぐ。
- 古いRenderTextureの内容を新しい評価結果と誤認することを防ぐ。
- ユーザーが停止原因をノードエディター上で追跡できるようにする。
