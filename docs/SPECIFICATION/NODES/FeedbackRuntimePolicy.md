# Feedbackノードの履歴運用

## 状態

ポート、初回映像、二重バッファ、コミット、リセットおよび仕様変更時の扱いは確定。

## ポート

- 入力Port IDは `input`、表示名は `Input`、型は `ImageFrame` とする。
- `Input` は任意入力で、既定映像は `TransparentBlack` とする。
- 出力Port IDは `image`、表示名は `Image` とする。

## 履歴

- Feedbackは同じ解像度・形式の2枚のRenderTextureを専用Leaseとして持つ。
- 評価時は前フレーム側のTextureを出力する。
- グラフ全体の通常評価完了後に、現在入力を次フレーム側へコピーして2枚を交換する。
- 初回評価、明示Reset、プロジェクト読込直後は透明黒を前フレームとして出力する。
- 入力を取得できない場合は任意入力規則に従い透明黒を次履歴へ記録する。

## リセットと変更

- ノードのカスタムUIに `Reset History` コマンドを設け、次の評価フレーム境界で履歴を透明黒へ戻す。
- Resetはパラメーターまたはプリセット対象にしない。
- ノードが評価対象外または無効な間は履歴を維持する。
- プリセット呼び出しでは履歴を変更しない。
- 解像度、HDR／LDR形式またはGraphicsFormatが変わった場合は新しい2枚を確保し、履歴を透明黒へリセットする。
- 履歴確保に失敗した場合はFaultedとし、最後に利用可能だった出力があればProgram終端の保持規則へ任せる。

## 設計意図

- 同一フレーム循環を二重バッファと後処理コミットで確実に切る。
- 仕様の異なるTexture間で古い履歴を誤用しない。
- プリセット切り替えで意図せずFeedback映像が消えないようにする。
