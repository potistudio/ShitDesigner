# ノードグラフ評価

## 状態

確定。

## 評価方式

Program出力と表示中のPreview出力を起点に、必要な上流ノードだけを逆引きして評価する。

## 確定事項

- 各評価フレームでは、Program出力が要求する映像から上流ノードをたどる。
- ノード評価を開始する前に、そのフレームで使用する全パラメーターの `EffectiveValue` を評価フレーム境界で確定する。
- 同じ評価フレーム内のノードは、途中で変更されない同一のパラメータースナップショットを参照する。
- グラフ内に1つだけ存在する固定 `ProgramOutput` ノードをProgram評価の起点とする。
- 表示中のPreview出力がある場合、そのPreviewが要求する映像からも上流ノードをたどる。
- 複数のPreviewノードが表示中の場合は、それぞれを評価の起点へ追加する。
- 表示中でないPreviewノードは評価の起点にしない。
- どの有効な出力からも到達できないノードは、そのフレームでは評価しない。
- 上流の依存ノードを、接続先ノードより先に評価する。
- 複数の出力や分岐から同じノードが要求されても、同一フレーム内ではそのノードを最大1回だけ評価する。
- 1回評価した結果は同一フレーム内で共有する。
- 1つの出力ポートが複数の入力ポートへ接続されている場合も、同じ評価結果を全接続先へ共有する。
- `ImageFrame` のフレーム番号を使い、同一フレームで生成済みの結果を識別できるようにする。
- 循環接続は `Feedback` ノードを経由する場合だけ許可する。
- `Feedback` ノードの出力は前フレームの保持結果として評価し、現在フレームの入力を同一フレーム内の依存関係に含めない。
- `Feedback` ノードを時間境界として扱い、同一フレーム内の評価順序は非循環に保つ。
- `Feedback` ノードを経由しない循環になる接続は拒否する。
- 必須入力を取得できないノードは `Blocked` 状態とし、そのフレームでは評価しない。
- `Blocked` 状態は依存する下流へだけ伝播させ、独立した枝の評価は継続する。
- 評価処理で例外または実行失敗が発生したノードは `Faulted` 状態とし、次の評価フレームで再試行する。
- `Faulted` ノードに依存しない枝の評価は継続する。
- Program出力の評価をPreview出力より優先する。
- 負荷が高い場合はProgramの1920×1080・60fps維持を優先し、Previewの評価頻度または要求解像度を自動的に下げる。
- Programと表示中Previewから要求解像度を上流へ伝播する。
- 同じノード出力へ複数の解像度要求が到達した場合は最大要求へ統合し、同一フレームに1回だけ評価する。
- 低い解像度を要求したPreviewは終端側で映像を縮小する。
- 異なるアスペクト比の要求は最も優先度が高い出力ターゲットへ合わせ、Programが含まれる場合はProgramの要求を採用する。
- Previewは終端側で `Fit`、`Fill`、`Stretch` を適用し、アスペクト比の違いによる上流の再評価は行わない。

## 設計意図

- Program映像と操作用Previewに不要な処理を実行しない。
- 未接続または未表示の3D描画、2D描画、シェーダー、動画などによるCPU・GPU負荷を避ける。
- ProgramとPreviewで上流処理を共有し、同じ映像を重複生成しない。
- 出力の増加や分岐があっても、1フレーム内の評価回数を予測しやすくする。
