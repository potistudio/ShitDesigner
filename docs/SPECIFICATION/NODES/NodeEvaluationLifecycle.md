# ノード評価フレームのライフサイクル

## 状態

グラフ編集、パラメーター確定、出力要求、リソース割り当て、ノード評価および後処理の順序は確定。

## 1フレームの順序

```text
1. GraphEditCommandを検証・適用
2. Parameter／Value／PresetTriggerイベントを確定
3. EffectiveValueスナップショットを生成
4. Programと表示中Previewから出力要求を収集
5. 必要な出力Leaseを確保
6. 上流から下流へ各ノードを最大1回評価
7. Feedbackの次フレーム履歴をコミット
8. Program／Previewへ結果を提示
9. 返却済みGPUリソースと破棄待ちSceneを後処理
```

## 状態伝播

- `Available` だけが現在フレームの値を下流へ渡す。
- 必須入力が `Blocked`、`Faulted`、`Preparing` またはBrokenの場合、下流ノードを `Blocked` とする。
- 任意入力では同じ状態を `UsingFallback` として既定値へ置き換える。
- ノード実行例外は `Faulted` とし、次の要求フレームで再試行する。
- 素材準備、Seek、Scene生成など正常な非同期待ちは `Preparing` とし、失敗扱いにしない。
- 非表示Previewは次の評価フレーム境界から評価起点を外す。

## 出力要求

- ノード作成時にはRenderTextureを割り当てない。
- 接続されていても、Programまたは表示中Previewから到達しない出力は要求しない。
- 初めて要求された出力だけLeaseを取得する。
- 1ノードに複数出力があっても、要求された出力だけを生成対象にする。
- ノード定義は要求出力集合を受け取り、1回の評価で必要な出力を生成する。

## 設計意図

- 編集途中や非同期途中の状態を同じフレームへ混ぜない。
- 不要なGPU割り当てと描画を避ける。
- 正常な待機と障害を区別して診断する。
