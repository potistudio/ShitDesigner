# ノード状態のバージョニング

## 状態

初期Version、逐次移行API、バックアップ、失敗時UnknownNodeおよび復旧方式まで確定。

## 確定事項

- 各ノード型定義は、ノード固有の整数 `SchemaVersion` を持つ。
- VJプロジェクトへ各ノードを保存するとき、型ID、`SchemaVersion`、インスタンス状態を記録する。
- 保存された `SchemaVersion` が現在のノード型定義より古い場合、ノード固有の移行処理を実行する。
- 移行処理は `v1 -> v2 -> v3` のように、1バージョンずつ順番に適用する。
- 各移行処理は、1つ前のバージョンの保存状態を次のバージョンへ変換する。
- ノード型ごとの `SchemaVersion` と、VJプロジェクト全体の形式バージョンを別々に管理する。
- 1つのノード型の状態構造を変更しても、無関係なノード型の `SchemaVersion` は変更しない。
- 新しいノード型を追加するだけの場合、既存ノード型の保存状態とプロジェクト共通構造を変更しない。
- 移行後の状態は、現在のノードFactoryへ渡してインスタンスを復元する。
- 型IDが未登録の場合は移行やFactory生成を行わず、型ID、`SchemaVersion`、生データを `UnknownNode` として保持する。

## 設計意図

- ノード型を個別に進化させながら、古いVJプロジェクトを読み込めるようにする。
- ノード固有変更とプロジェクト全体の形式変更を分離する。
- 段階移行によって、すべての旧バージョンから最新版への直接変換を個別実装する必要をなくす。
