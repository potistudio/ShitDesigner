# NodeTypeRegistry

## 状態

共通登録契約、型ID命名、Factory API、ビルド生成カタログおよび重複検証まで確定。

## 役割

Standaloneアプリで利用できるすべてのノード型を一元登録し、追加UI、インスタンス生成、保存データ読込に共通の定義を提供する。

## 確定事項

- 3D、2D、Shader、動画、加工、合成、変換を含むすべてのノード型を、共通の `NodeTypeRegistry` へ登録する。
- 各ノード型定義は、グローバルに一意で安定した型IDを持つ。
- 各ノード型定義は、ノードインスタンスを生成するFactoryを持つ。
- 各ノード型定義は、入力ポート、出力ポート、パラメーターの定義を持つ。
- 各ノード型定義は、ノード追加UIで使用する表示名とカテゴリを持つ。
- カテゴリは検索と表示整理のためのメタデータであり、評価方式や保存形式を分岐させない。
- ノード追加UIは `NodeTypeRegistry` を検索し、登録済みの生成可能なノード型を提示する。
- VJプロジェクト読込時は、保存された型IDを `NodeTypeRegistry` で解決し、対応するFactoryからインスタンスを生成する。
- ノードグラフの共通保存構造はノード型IDとインスタンス状態を保持し、ノード種類ごとの専用保存コンテナーを要求しない。
- 新しいノード型を登録しても、既存ノードグラフの共通保存構造を全面変更しない。
- 種類ごとに独立したレジストリを作らない。
- Reflectionによる実行時の自動検出を、初期版の必須登録方式にしない。
- 各ノード型定義は固有の `SchemaVersion` と段階的な状態移行処理を持つ。
- プロジェクト保存時はノード型IDと `SchemaVersion` を記録し、読込時は必要な移行を順番に適用してからFactoryで復元する。
- ノード型の `SchemaVersion` はVJプロジェクト全体の形式バージョンと分離する。
- 保存された型IDが未登録の場合は、元データと接続を保持する `UnknownNode` プレースホルダーとして読み込む。
- 対応するノード型が追加された後、`UnknownNode` の保持データから本来のノードへ復元できるようにする。

## 設計意図

- ノード追加、生成、保存、復元の処理を種類ごとに重複させない。
- 新しいノード種別を共通契約へ追加できるようにする。
- IL2CPPでの実行時型検出やコード除去へ依存せず、登録内容を明示的に管理できるようにする。
- カテゴリ再編が保存データや評価処理へ影響しないようにする。
