# パラメーターの基底値と実効値

## 状態

`BaseValue` と `EffectiveValue` の分離、論理コントロール合成式からの参照方法、両方をUIへ表示する方針、および評価フレーム境界での反映順序は確定。

## 役割

UIやプリセットで設定する保存値と、論理コントロールの合成後にノードが実際に使用する値を分離する。

## 確定事項

- 各パラメーターは、保存対象となる `BaseValue` と、ノード評価に使用する `EffectiveValue` を持つ。
- UI、カスタムUIおよびプリセットは `BaseValue` を変更する。
- 論理コントロールの合成式は、葉として `Base` を明示的に配置できる。
- `Base` 葉は、その評価フレームに確定した対象パラメーターの `BaseValue` を返す。
- 合成式に `Base` 葉が含まれる場合、`BaseValue` は保存された式ツリー上の位置に従ってMin／Max合成へ参加する。
- 合成式に `Base` 葉が含まれない場合、`BaseValue` は合成へ参加せず、論理コントロール値だけで `EffectiveValue` を決める。
- 合成式が割り当てられていない場合、`EffectiveValue` は `BaseValue` と同じ値になる。
- 合成式の評価結果は `EffectiveValue` だけを更新し、`BaseValue` へ書き戻さない。
- `EffectiveValue` は派生した実行時状態であり、パラメーター値またはプリセット値として保存しない。
- プロジェクトには `BaseValue` と合成式を保存し、読込後にそれらから `EffectiveValue` を再計算する。
- 任意入力ポートが未接続の場合は、参照先パラメーターの `EffectiveValue` を入力値として使用する。
- 任意入力ポートが接続されている場合は接続値を優先し、`BaseValue` と合成式は背後で保持する。
- パラメーターUIでは、`BaseValue` を編集欄、`EffectiveValue` を読み取り専用モニターとして同時に表示する。
- 1評価フレーム内に届いた `BaseValue` と論理コントロールの変更は、次の評価フレーム境界まで収集する。
- 評価フレーム境界で更新後の `BaseValue` と最新の論理コントロール値を確定し、同じスナップショットから `EffectiveValue` を1回計算する。
- ノードグラフは、計算済みの `EffectiveValue` をそのフレーム中変更せずに使用する。

## 例

```text
Max
├─ Base
└─ Min
   ├─ Control A
   └─ Control B
```

上記は `Max(Base, Min(A, B))` を表す。`Base` を削除すれば、同じパラメーターを論理コントロールだけで完全に制御できる。

## 設計意図

- 手動設定やプリセットの値を失わずに、ライブ中の論理コントロールを重ねられるようにする。
- 基底値を合成へ参加させるかを、暗黙の規則ではなく式ツリー上で明示する。
- 論理コントロールを解除したとき、保存されていた基底値へ戻れるようにする。
