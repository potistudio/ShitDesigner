# パラメーターUI契約

## 状態

標準UIのメタデータ、表示構造、カスタムUIの権限および更新頻度は確定。

## 必須メタデータ

- `ParameterId`、表示名、型、既定値、表示順を必須とする。
- 説明、グループ、単位は省略可能で、既定値は空文字とする。
- 数値の刻み幅は省略可能とし、省略時は連続入力を使用する。
- ハード範囲を定義した場合は、UI操作部品の入力範囲にも使用する。
- 公開状態は `Editable`、`ReadOnly`、`Hidden` のいずれかとする。

## 標準レイアウト

- パラメーターをグループごとの折り畳みセクションに分け、表示順、次に `ParameterId` の順で安定して並べる。
- 各行は表示名、編集可能な `BaseValue`、読み取り専用の `EffectiveValue`、単位、状態表示を持つ。
- `BaseValue` と `EffectiveValue` が同じ場合も両方を表示し、実効値側を弱い色で示す。
- VectorはX／Y／Z／W、ColorはRGBとAlphaを分けて表示し、各成分の範囲を反映する。
- 全成分へ同じ値または範囲を入力する一括操作を補助機能として提供する。
- クランプ、参照切れ、検証失敗は対象行へインライン表示する。

## 更新頻度

- 表示中の `EffectiveValue` はStandalone UIの描画フレームごとに最大1回更新する。
- 画面外または折り畳み中の行は描画更新を止めるが、内部値の評価は止めない。
- 再表示時は最新スナップショットを即座に表示する。

## カスタムUI

- カスタムUIは `NodeTypeId` に対応する明示的なUI Factoryとしてランタイムカタログへ登録する。
- カスタムUIは標準行を置き換えたり補助表示を追加できる。
- カスタムUIも共通パラメーターAPIだけを使い、ノード実装へ直接書き込まない。
- `EffectiveValue` は常に読み取り専用とする。
- カスタムUIがあっても、診断用の標準パラメーター一覧を別パネルから開けるようにする。
- Factory生成に失敗した場合は標準UIへフォールバックし、ノード自体は動作を継続する。

## 設計意図

- 新規ノードをメタデータだけで操作可能にする。
- 特殊UIを許しながら、保存、検証、プリセットおよび論理コントロールの経路を統一する。
- 非表示UIの無駄な再描画を避ける。
