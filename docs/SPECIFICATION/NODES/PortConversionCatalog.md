# ポート変換カタログ

## 状態

暗黙変換ID、バージョニング、重複規則、欠落時および実行失敗時の扱いは確定。

## 初期暗黙変換

- `core.color_to_vector4.v1`: `core.color_linear` から `core.vector4f` へRGBAをそのまま渡す。
- `core.vector4_to_color.v1`: `core.vector4f` から `core.color_linear` へXYZWをRGBAとしてそのまま渡す。
- 上記2変換だけを初期版の暗黙変換とする。
- どちらも32bit float 4成分のビット値を維持し、色空間変換、クランプ、Premultiplyを行わない。

## 登録とバージョン

- 変換IDは `vendor.source_to_target.vN` 形式の小文字ASCIIとする。
- 公開済み変換の意味を変更せず、挙動変更時は新しいバージョンの変換IDを追加する。
- 同じ変換元・変換先へ複数の直接変換を登録できるが、暗黙接続の既定変換は1つだけとする。
- 既定変換の重複はビルドおよび起動時検証を失敗させる。
- 接続保存データは実際に選択した変換IDを保持する。

## 情報保持判定

- 暗黙変換は、全入力値について元の情報を保持し、逆変換との往復テストに成功するものだけ許可する。
- 手動レビューと自動ラウンドトリップテストの両方を登録条件とする。
- IntとFloatのように一部値で精度を失う変換は暗黙変換へ登録しない。

## 欠落と失敗

- 保存された変換IDが見つからない接続は削除せず `BrokenConnection` として保持する。
- `BrokenConnection` は値を渡さず、必須入力をBlocked、任意入力をフォールバックさせる。
- 変換実行が例外または失敗を返した場合は `ConversionFault` を記録し、同じ下流規則を使う。
- 別の変換を暗黙に選び直さない。

## 設計意図

- アプリ更新後も保存時と同じ変換を再現する。
- 精度損失をユーザーの見えない接続処理へ入れない。
- 欠落変換をデータ削除ではなく修復可能な接続状態として扱う。
