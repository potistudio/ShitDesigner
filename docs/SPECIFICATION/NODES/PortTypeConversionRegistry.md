# ポート型変換レジストリ

## 状態

基本契約、初期変換ID、バージョニング、重複規則および失敗時の扱いまで確定。

## 役割

ポート型の暗黙変換をシステム全体で一元管理し、接続時と評価時に同じ変換を再現できるようにする。

## 確定事項

- 暗黙変換は中央の型変換レジストリへ登録する。
- 各変換定義は、変換元の型、変換先の型、変換ID、変換処理を持つ。
- 変換元から変換先への直接変換が登録されている場合だけ、異なる型同士を接続できる。
- 複数の変換を連結した変換経路は自動探索しない。
- 接続を作成するときに、使用する直接変換をレジストリから解決する。
- 変換が見つからない場合、その接続操作を拒否する。
- 接続データは、接続時に解決した変換IDを保存する。
- グラフ評価時は、接続データに保存された変換IDの変換処理を使用する。
- レジストリへ別の変換が追加されても、保存済み接続が使用する変換IDを自動的に変更しない。
- レジストリが暗黙変換として提供するのは、元の情報を失わない直接変換だけとする。
- 情報を失う変換はレジストリの暗黙変換として提供せず、専用の変換ノードで行う。
- 初期版では `Color` から `Vector4` と、`Vector4` から `Color` の直接変換だけを登録する。

## 設計意図

- どの暗黙変換が実行されるかを一意にする。
- ノードごとに同じ変換処理を重複実装しない。
- VJプロジェクトを保存して開き直した後も、接続の変換結果を再現できるようにする。
- 変換の追加によって既存プロジェクトの動作が意図せず変わることを防ぐ。
- 評価時に変換経路を探索せず、実行コストを予測しやすくする。
