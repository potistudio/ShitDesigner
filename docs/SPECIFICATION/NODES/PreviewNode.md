# Previewノード

## 状態

基本契約、正式名、表示UI、同時表示上限および性能制御まで確定。

## 役割

任意の映像出力を操作者が確認するためのPreviewを、ノードグラフ内へ追加する。

## 確定事項

- `Preview` は通常の追加・削除可能なノードとして扱う。
- グラフ内へ複数の `Preview` ノードを配置できる。
- 各 `Preview` ノードは、表示する映像を受け取る必須の `ImageFrame` 入力を1つ持つ。
- `Preview` ノードは映像をグラフ外の操作用Previewへ渡す終端ノードであり、出力ポートを持たない。
- ユーザーはStandaloneアプリの実行中に `Preview` ノードを追加、削除、接続、切断できる。
- 複数の `Preview` ノードを使用して、複数の映像を同時に確認できる。
- 表示中の `Preview` ノードはグラフ評価の起点になる。
- 表示中でない `Preview` ノードは、そのノードだけを理由として上流評価を要求しない。
- `Preview` ノードとその入力接続はVJプロジェクトの保存対象に含め、再読込時に復元する。
- Preview対象が `Blocked` または `Faulted` の影響を受けた場合、そのPreviewへ原因を示す診断表示を重ねる。
- Previewの診断表示はProgram映像へ混入させない。
- Program出力をPreviewより高い評価優先度で扱う。
- 処理負荷が高い場合、Programの1920×1080・60fps維持を優先し、Previewの更新頻度または解像度を自動的に下げる。
- Previewが自動抑制中であることを操作画面へ表示する。
- 各Previewは表示に必要な解像度を上流へ要求し、自動抑制中は抑制後の解像度を要求する。
- Programなどの高解像度要求と上流を共有する場合は共有結果を利用し、Preview終端で必要な解像度へ縮小する。
- 上流とPreview表示領域のアスペクト比が異なる場合、Preview終端で `Fit`、`Fill`、`Stretch` のいずれかを適用する。
- 表示方式はPreviewノードごとの保存パラメーターとし、既定値は `Fit` とする。
- 内部Linear映像をPreview表示先が要求する色空間へ終端で変換する。
- 正式表示名は `Preview`、型IDは `system.preview` とする。
- ノード本体へサムネイルを表示し、ダブルクリックでドッキングPreviewパネルを開く。
- 同時表示上限は8個とし、通常品質は640×360・30fpsとする。

## 設計意図

- Program接続を変更せず、複数地点の映像を同時確認できるようにする。
- 必要なPreviewだけを評価対象にし、非表示Previewによる不要な処理を避ける。
- Preview構成をグラフの一部として保存、復元できるようにする。
