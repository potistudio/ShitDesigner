# Preview性能優先度

## 状態

優先順位、負荷判定、品質段階、抑制順および復帰ヒステリシスまで確定。

## 確定事項

- Program出力の描画を、すべてのPreview出力より高い優先度で扱う。
- Program映像の1920×1080・60fps維持を優先する。
- 複数Previewによって処理負荷が高くなった場合、Program側ではなくPreview側を自動的に抑制する。
- Previewの自動抑制では、Previewの更新頻度を下げることができる。
- Previewの自動抑制では、Previewの解像度を下げることができる。
- Previewを抑制しても、Program映像の解像度、更新頻度、出力内容を変更しない。
- Previewが抑制中であることを操作画面で確認できるようにする。
- 負荷が回復した場合、Preview品質を通常設定へ自動的に戻せるようにする。
- 品質段階は640×360@30、480×270@30、320×180@20、160×90@10、160×90@5とする。
- CPUまたはGPU Frame Timeが15.5msを30フレーム連続で超えた場合に1段階下げる。
- CPUとGPUの両方が13.5ms未満を180フレーム維持した場合に2秒ごと1段階ずつ戻す。
- 非フォーカスPreviewを古い順に抑制し、フォーカス中Previewは最後に抑制する。

## 設計意図

- 操作用Previewの数や表示状態によって、観客向けProgram映像がフレーム落ちすることを防ぐ。
- ライブ中の出力安定性を、操作画面の滑らかさや精細さより優先する。
- Previewを削除または手動停止しなくても、システムが負荷を局所的に調整できるようにする。
