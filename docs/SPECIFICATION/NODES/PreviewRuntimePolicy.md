# Previewの表示と自動品質制御

## 状態

ノード名、表示UI、同時表示数、通常品質、負荷判定、品質段階および復帰条件は確定。

## UI

- ノード表示名は `Preview`、型IDは `system.preview` とする。
- Previewノード本体へサムネイルを表示し、ダブルクリックで大きなドッキングPreviewパネルを開く。
- ノードの目アイコンまたはパネルを閉じる操作で表示／非表示を切り替える。
- 表示方式 `Fit`、`Fill`、`Stretch` は実行中に切り替え、プロジェクトへ保存する。
- 同時に表示できるPreviewは8個までとし、9個目を表示する操作は拒否して理由を示す。

## 品質段階

| 段階 | 解像度 | 更新頻度 |
|---:|---:|---:|
| 0 | 640×360 | 30fps |
| 1 | 480×270 | 30fps |
| 2 | 320×180 | 20fps |
| 3 | 160×90 | 10fps |
| 4 | 160×90 | 5fps |

- 通常は段階0を使用する。
- Programはこの品質制御の対象にしない。

## 負荷判定

- `FrameTimingManager` のCPU Frame TimeとGPU Frame Timeを移動平均で計測する。
- どちらかが `15.5ms` を30フレーム連続で超えた場合、Preview品質を1段階下げる。
- 解像度低下を先に行い、その後に更新頻度を下げる。
- 非フォーカスPreviewを、最後にフォーカスされた時刻が古い順に抑制する。
- フォーカス中Previewは他の表示中Previewが最低段階へ到達するまで抑制しない。
- CPUとGPUの両方が `13.5ms` 未満の状態を180フレーム維持した場合、2秒に1段階ずつ品質を戻す。

## 状態表示

- Blockedは透明黒背景へ原因ノードと不足入力を表示する。
- Faultedは暗赤色の診断オーバーレイ、Preparingは進行表示、UsingFallbackは黄色バッジを使う。
- 自動抑制中は現在の解像度と更新頻度を表示する。

## 設計意図

- Programの60fpsを守りながら、操作に必要なPreviewを可能な範囲で維持する。
- 品質低下と復帰に継続条件を設け、頻繁な揺れを防ぐ。
- Previewノードと大画面確認の両方を同じ評価起点へ結び付ける。
