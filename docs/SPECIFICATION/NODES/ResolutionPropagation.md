# RenderTexture解像度の伝播

## 状態

基本方式、要求統合、アスペクト優先順位、固定Program解像度およびノード解像度規則まで確定。

## 確定事項

- RenderTextureの要求解像度は、Programおよび表示中Previewの出力ターゲットから上流ノードへ伝播する。
- Program出力は初期版で固定の1920×1080映像を要求する。
- 各Previewノードは、そのPreviewに必要な解像度を要求する。
- Previewの自動抑制中は、抑制後のPreview解像度を要求として使用する。
- 1つのノード出力へ複数の解像度要求が到達した場合、要求を満たす最大解像度へ統合する。
- 共有ノードは、統合した解像度で同一フレームに1回だけ評価する。
- 統合解像度より低い解像度を要求したPreviewは、Preview終端側で映像を縮小する。
- Programと共有されないPreview専用の枝は、そのPreviewが要求する解像度で評価できる。
- 解像度要求が変わり、出力RenderTextureの条件が変化した場合は、出力ポートの継続貸出を新しい条件へ切り替える。
- 実際に生成した幅と高さは `ImageFrame` の解像度情報へ記録する。
- 異なるアスペクト比の要求がある場合は、最も優先度が高い出力ターゲットのアスペクト比を採用する。
- ProgramとPreviewが共有するノードではProgramのアスペクト比を優先し、Preview終端で `Fit`、`Fill`、`Stretch` のいずれかを適用する。
- 初期版の各映像ノードは統合要求解像度をそのまま採用し、固定解像度や倍率指定を持たない。
- 縮小にはBilinearフィルターを使用し、要求変更は評価フレーム境界で反映する。

## 設計意図

- ProgramとPreviewの共有処理を同一フレーム内で重複評価しない。
- Preview専用処理を必要以上に高い解像度で実行しない。
- Preview品質を下げたとき、上流処理のGPU負荷も削減できるようにする。
- 解像度変更後も、接続先が実際の映像サイズを確認できるようにする。
