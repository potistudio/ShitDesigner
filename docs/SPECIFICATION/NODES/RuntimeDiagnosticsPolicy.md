# ランタイム診断ポリシー

## 状態

Blocked、Faulted、Preparing、フォールバック、ログ抑制および履歴保持の規則は確定。

## 診断データ

- 診断は `DiagnosticCode`、Severity、NodeInstanceId、NodeTypeId、Port／Parameter ID、短いメッセージ、詳細、FrameNumber、GraphClock時刻を持つ。
- 例外が原因の場合は例外型とスタックトレースを詳細へ含める。
- 診断状態は実行時派生状態であり、VJプロジェクトへ保存しない。

## 状態

- `Blocked`: 必須依存を取得できない。通常の構成状態としてUI表示し、遷移をログへ残さない。
- `Faulted`: ノード実行、変換、素材読込またはGPU処理の失敗。診断履歴へ記録する。
- `Preparing`: Scene生成、動画Prepare、Seekなどの正常な待機。エラーログへ記録しない。
- `UsingFallback`: 任意入力が既定値を使用中。入力ソケットへ表示し、通常ログへ記録しない。
- `HoldingLastFrame`: Programが最後の正常フレームを提示中。操作画面へ原因を表示する。

## 再試行と抑制

- Faultedノードは要求されている限り次の評価フレームで再試行する。
- 同じ `DiagnosticCode` と詳細が連続する場合、最初の1件を記録し、その後は件数だけを集約する。
- 継続障害は300フレームごとに集約件数を更新し、新規行を増やさない。
- 回復時は回復イベントと継続フレーム数を1件記録する。

## 履歴

- セッション診断履歴は最新1000件のリングバッファとする。
- 履歴はプロジェクトへ保存せず、ユーザー操作でテキストまたはJSONへ書き出せる。
- UIはSeverity、ノード、コードでフィルターできる。

## 設計意図

- 正常な未接続や待機を障害ログで埋めない。
- 毎フレーム失敗するノードがメモリとUIを圧迫しないようにする。
- 障害からの回復を確認できるようにする。
